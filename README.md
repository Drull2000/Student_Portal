# Компьютерная Инженерия

Статический портал группы с расписанием, онлайн-занятиями, важными ссылками и защищённой админ-панелью на Supabase.

## Как открыть сайт

Откройте `index.html` в браузере. Для корректной работы Supabase и PDF рекомендуется использовать Live Server в VS Code или опубликовать проект на GitHub Pages, Netlify или Vercel.

## Как добавить расписание PDF

1. Положите текущий PDF в папку `assets/`.
2. Назовите файл `schedule.pdf`.
3. Главная страница автоматически покажет этот файл.
4. При изменении расписания просто замените PDF новым файлом с тем же именем.

PDF доступен только для просмотра. На главной странице есть кнопки для открытия в новой вкладке и скачивания.

## Как заменить значок на фотографию

Положите свою фотографию в папку `assets/` и назовите её `logo.jpg`. Она автоматически появится слева от названия сайта на всех страницах.

Если используется другой формат, например PNG, замените `logo.jpg` на `logo.png` в тегах `img` в HTML-файлах.

## Как изменить настройки сайта

### Админ-панель Supabase

В проект добавлена защищённая панель `admin.html`. Она позволяет менять настройки сайта, добавлять быстрые ссылки, Zoom, Google Classroom и Telegram, а также загружать новый PDF расписания.

1. Создайте проект на [Supabase](https://supabase.com/).
2. Откройте SQL Editor и выполните содержимое `supabase-schema.sql`.
3. В разделе Authentication создайте пользователя с email и паролем.
4. Войдите в админ-панель под первым пользователем, которому добавили права вручную через SQL, либо через `insert into public.admin_users (user_id) values ('UUID_ПОЛЬЗОВАТЕЛЯ');`.
5. После входа в админ-панель откройте раздел «Администраторы» и добавьте нужные email-адреса. Для этого система ищет существующих пользователей в Auth и назначает им права администратора.
6. Вставьте Project URL и **publishable/anon key** в `js/supabase-config.js`.
7. Включите Realtime для таблиц `site_settings`, `quick_links` и `resources`.
8. Откройте `/admin.html` на опубликованном сайте и войдите.

Публичный ключ можно хранить в GitHub: доступ ограничивается политиками RLS. Никогда не добавляйте в репозиторий `service_role` key, пароли или другие секретные ключи.

До подключения Supabase сайт использует резервные данные из `js/site-data.js`, поэтому локальная версия продолжает открываться.

Для Google Docs установите доступ **Все, у кого есть ссылка — читатель**. На странице расписания есть отдельная кнопка на случай, если просмотр внутри сайта недоступен.

Все быстрые ссылки, занятия Zoom, Google Classroom и Telegram редактируются через `admin.html`. Резервные данные для работы без Supabase хранятся в `js/site-data.js`.

## Размещение через GitHub Pages

1. Создайте репозиторий на GitHub.
2. Загрузите содержимое этой папки в репозиторий, включая `assets/schedule.pdf`.
3. Откройте **Settings → Pages**.
4. Выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`.
5. Сохраните настройки и дождитесь публикации.
6. Откройте `https://ИМЯ_ПОЛЬЗОВАТЕЛЯ.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.
7. Админ-панель будет доступна по адресу `/admin.html`.

После публикации добавьте адрес GitHub Pages в Supabase: **Authentication → URL Configuration → Site URL**. Это нужно для корректной работы Auth в опубликованной версии.

В проекте нет серверной части, базы данных или сборки, поэтому его также можно разместить на Netlify, Vercel или любом другом статическом хостинге.
